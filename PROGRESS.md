## Известные проблемы

- Предсказание движения клиента отсутствует (запланировано после T2.2)
- Rust-тулчейн на машине разработчика — stable GNU (MSVC Build Tools не установлены); при переходе в CI поменять хост на windows-msvc или ubuntu
- Комнаты интереса живут вечно (RoomAllocator не переиспользует id) — для долгих сессий добавить переиспользование; фазу 2 не блокирует
- Пол не имеет коллайдера — только стены; выпадение за карту появится как механика в T4.3 (симуляция атмосферы)
- Карта грузится сервером из assets/maps/test.ron (T2.3); чанки реплицируются клиенту с учётом интереса — клиент ничего не генерирует
- Формат карты — текстовые строки тайлов (' ' космос, '.' пол, '#' стена); генерация: `cargo run -p ssr-core --bin gen-map -- assets/maps/test.ron`
- Двери (T3.1): позиции в поле `doors` файла карты; клик мышью → Interact → серверная валидация радиуса 1.5 тайла → toggle + ColliderDisabled; состояние реплицируется всем клиентам
- Тестовые режимы: клиент — SSR_AUTO_WALK(+_MS, +_DIR), SSR_INTERACT_TEST, SSR_INV_TEST, SSR_LOCK_INPUT, SSR_LOBBY/SSR_AUTO_PLAY; сервер — SSR_MAP, SSR_DAMAGE_TEST, SSR_ROLE, SSR_SPECIES, SSR_BREACH_TEST, SSR_VACUUM_TEST, SSR_ATMOS_LOG, SSR_POWER_TEST; оба — SSR_PORT; клиент — SSR_DUMP_ONLY (офлайн-дамп чанков в PNG), SSR_DEBUG_BODY, SSR_CRAFT_TEST, SSR_LOBBY_AUTO, SSR_ADMIN_TEST, SSR_NAME, SSR_KICK_TEST, **SSR_BOT=<имя> (headless-бот)**; сервер — SSR_OPEN_ADMIN, SSR_ADMINS, SSR_PERF_LOG
- Инвентарь (T3.2): `Inventory` 7×4 (u64-bits предметов, ADR-7) + `Item` в core; сервер выдаёт демо-предметы, `TransferItem` валидирует владение/дистанцию/слот
- **Стройка/разрушение (T3.3)**: `UseItem` — сервер по имени предмета решает (SteelSheet строит, Crowbar ломает); тайл меняется в `TileChunkData` (реплицируется), коллайдеры чанка пересобираются; **запрет стройки на тайле любого игрока**; материал возвращается ломом; SSR_BUILD_TEST
- **Руки (SS14-модель)**: `Hands {active, slots[2]}` — активная рука, взять из рюкзака (клик по слоту), убрать в рюкзак (клик по активной руке), переключение рукой; `HeldBy` + иконка предмета у спрайта держателя
- **Атака (T4.1-мини)**: `Health` 100hp, урон 15 (лом) / 5 (кулак), смерть → возврат на спавн; лог `attack hit`
- **Действия (verbs)**: ПКМ по игроку/тайлу → `RequestActions` → сервер шлёт «Ударить»/«Открыть-Закрыть»/«Построить»/«Разобрать» → клик → `PerformAction`; единая очередь `ActionQueue` (Interact/UseItem/Attack), SSR_ATTACK_TEST
- **Визуалы других игроков** появились (раньше их вообще не было видно)
- Доказано живым прогоном: `item taken in hand`, `attack hit hp=95`, `build: tile occupied by a player (tx=2 — там стоял второй игрок)`, `tile built`, пользовательская стройка кликом
- **Контейнеры (T3.4)**: ящики в мире (`Container {open,name}` + `Inventory` + `ItemPosition`, реплицируются) с запасом предметов; клик по ящику или правый клик → «Открыть/Закрыть ящик»; панель открытого ящика рядом с игроком (клик по предмету — взять, по пустому слоту — положить из руки); `TransferItem` обобщён: источник — рюкзак/руки/ОТКРЫТЫЙ ящик рядом, приёмник — игрок или открытый ящик; закрытый ящик недоступен. Спрайт `Structures/Storage/Crates/generic.rsi` (closed/open). SSR_CONTAINER_TEST. Доказано: открытие→взятие (slot=3)→закрытие→«item is not available to sender»
- **Здоровье и урон (T4.1)**: урон идёт событиями — `DamageEvent {target, amount, source: Melee{attacker, weapon}}` → `apply_damage` (Health − amount, лог `damage applied` с killer/weapon/hp, при нуле — `DeathEvent`) → `respawn_dead` (лог `player died and respawned`, хп к максимуму, тело на точку спавна); клиент — HUD «HP 100/100» слева внизу (цвет по значению); тест сервера SSR_DAMAGE_TEST=1 (25 урона/сек первому игроку). Доказано: hp 75→50→25→0 → респавн (16,16); HUD клиента 100→75→50→25→100
- **Порт сервера настраивается `SSR_PORT`** (по умолчанию 7777): тестовые прогоны идут на отдельном порту и не перехватывают живую игру (урок 04.10.2026: тестовый сервер на 7777 высасывал хп у игравшего владельца)
- **Роли (T4.2)**: `assets/prototypes/roles.ron` — инженер / ассистент / предатель (название, стартовый инвентарь, доступы, антагонист с целью); сервер выдаёт роль по кругу (`SSR_ROLE=<id>` — фиксированная), инвентарь — из роли; игрок получает `PlayerRole` (реплицируется — клиент показывает роль и цель в HUD) и `Access` (только сервер). Двери могут требовать ключ (`door_access` в карте, поле `access` у `Door`): открывает только роль с ключом, в verbs недоступная дверь не предлагается. Доказано: инженер — `door toggled open=true`; ассистент — `door access denied required="engineering"`, дверь не открылась
- **Фикс ящика**: `generic.rsi` — это `base` (корпус) + `closed`/`open` (крышка) отдельными стейтами; клиент рисует корпус и крышку поверх (раньше была видна только крышка)
- Рендер мира: чанк — одна картинка 1024×1024 (сборка с учётом соседних чанков); стены с угловым сглаживанием по правилам движка (IconSmooth/Corners: 4 слоя solid0..7, N/E/S/W + диагонали); ряд ly=0 — низ чанка (отражение по Y обязательно, иначе боксы не совпадают со спрайтами); пересборка через кадр стабильности набора чанков
- Движение клиента: интерполяция строго между двумя последними серверными позициями за тик сети (без экспоненциального сглаживания), камера жёстко следует за отрисованным игроком
- Спрайты: стены — Structures/Walls/solid.rsi (угловое сглаживание: слои SE/NE/NW/SW берут ячейки d0/d2/d1/d3; патчи-четверти), двери — Doors/Airlocks/Standard/basic.rsi (closed/open + анимация opening/closing по delays), игрок — monkey.rsi с выбором 1 из 4 направлений по движению
- **Порядок направлений RSI в движке: South=0, North=1, East=2, West=3** (не S,E,N,W!) — ошибка в этом маппинге давала неверные стороны игрока и четверти стен
- Карты SS14: staging в assets/maps/ss14/ (empty, floor3x3, admin_test_arena, aspid — формат 7 со словарём tilemap); импорт в игровой .ron — задача IMP.4
- Всплывающая обводка объектов под курсором (сейчас двери; для предметов — в T3.2)
- **Импорт контента SS14 (IMP.2–IMP.4)**: крейт `ssr-tools` —
  `import-map` (карты формата 6/7 → наш .ron; тайлы по коду движка MapChunkSerializer),
  `import-proto` (прототипы YAML с наследованием → `assets/prototypes_ss14.ron`, 9258 шт.),
  `import-sprites` (копирование RSI по списку `tools/sprites_ss14.txt`, 2533 папки/41 МБ)
- Карты SS14: `assets/maps/imported_aspid.ron` (реальная станция: 20 чанков, 1385 стен, 204 двери) и `imported_floor3x3.ron`; выбор карты — `SSR_MAP=<файл>.ron`
- **Лобби** по образцу мини-станции (`LobbyGui.xaml` + их `AnimatedBackgroundControl`): полноэкранный **анимированный фон** `_Mini/Lobby/mars.rsi` (64 кадра, delays из RSI), верхняя панель-страйп с кнопками «Правила»/«Вики» и логотипом справа, внизу слева ServerInfo, в центре «Смена ещё не началась» + «Готов»/«Выход». Показывается ТОЛЬКО в release (dev сразу в игру; `SSR_LOBBY=1` — отладка, `SSR_AUTO_PLAY=1` — тесты)
- Загрузчик RSI перепаковывает листы, не влезающие в лимит GPU (16384 px): лента 64×320 = 20480 px фона лобби падала с Validation Error
