## Известные проблемы

- Предсказание движения клиента отсутствует (запланировано после T2.2)
- Rust-тулчейн на машине разработчика — stable GNU (MSVC Build Tools не установлены); при переходе в CI поменять хост на windows-msvc или ubuntu
- Комнаты интереса живут вечно (RoomAllocator не переиспользует id) — для долгих сессий добавить переиспользование; фазу 2 не блокирует
- Пол не имеет коллайдера — только стены; выпадение за карту появится как механика в T4.3 (симуляция атмосферы)
- Карта грузится сервером из assets/maps/test.ron (T2.3); чанки реплицируются клиенту с учётом интереса — клиент ничего не генерирует
- Формат карты — текстовые строки тайлов (' ' космос, '.' пол, '#' стена); генерация: `cargo run -p ssr-core --bin gen-map -- assets/maps/test.ron`
- Двери (T3.1): позиции в поле `doors` файла карты; клик мышью → Interact → серверная валидация радиуса 1.5 тайла → toggle + ColliderDisabled; состояние реплицируется всем клиентам
- Тестовые режимы: клиент — SSR_AUTO_WALK(+_MS, +_DIR), SSR_INTERACT_TEST, SSR_INV_TEST, SSR_LOCK_INPUT, SSR_LOBBY/SSR_AUTO_PLAY; сервер — SSR_MAP, SSR_DAMAGE_TEST, SSR_ROLE, SSR_SPECIES, SSR_BREACH_TEST, SSR_VACUUM_TEST, SSR_ATMOS_LOG, SSR_POWER_TEST; оба — SSR_PORT; клиент — SSR_DUMP_ONLY (офлайн-дамп чанков в PNG), **SSR_SCREENSHOT=<файл> (клиент сам сохраняет кадр)**, SSR_DEBUG_BODY, SSR_CRAFT_TEST, SSR_LOBBY_AUTO, SSR_ADMIN_TEST, SSR_NAME, SSR_KICK_TEST, SSR_RUN_TEST, SSR_MECH_TEST, **SSR_BOT=<имя> (headless-бот)**; сервер — SSR_OPEN_ADMIN, SSR_ADMINS, SSR_PERF_LOG
- Инвентарь (T3.2): `Inventory` 7×4 (u64-bits предметов, ADR-7) + `Item` в core; сервер выдаёт демо-предметы, `TransferItem` валидирует владение/дистанцию/слот
- **Стройка/разрушение (T3.3)**: `UseItem` — сервер по имени предмета решает (SteelSheet строит, Crowbar ломает); тайл меняется в `TileChunkData` (реплицируется), коллайдеры чанка пересобираются; **запрет стройки на тайле любого игрока**; материал возвращается ломом; SSR_BUILD_TEST
- **Руки (SS14-модель)**: `Hands {active, slots[2]}` — активная рука, взять из рюкзака (клик по слоту), убрать в рюкзак (клик по активной руке), переключение рукой; `HeldBy` + иконка предмета у спрайта держателя
- **Атака (T4.1-мини)**: `Health` 100hp, урон 15 (лом) / 5 (кулак), смерть → возврат на спавн; лог `attack hit`
- **Действия (verbs)**: ПКМ по игроку/тайлу → `RequestActions` → сервер шлёт «Ударить»/«Открыть-Закрыть»/«Построить»/«Разобрать» → клик → `PerformAction`; единая очередь `ActionQueue` (Interact/UseItem/Attack), SSR_ATTACK_TEST
- **Визуалы других игроков** появились (раньше их вообще не было видно)
- Доказано живым прогоном: `item taken in hand`, `attack hit hp=95`, `build: tile occupied by a player (tx=2 — там стоял второй игрок)`, `tile built`, пользовательская стройка кликом
- **Контейнеры (T3.4)**: ящики в мире (`Container {open,name}` + `Inventory` + `ItemPosition`, реплицируются) с запасом предметов; клик по ящику или правый клик → «Открыть/Закрыть ящик»; панель открытого ящика рядом с игроком (клик по предмету — взять, по пустому слоту — положить из руки); `TransferItem` обобщён: источник — рюкзак/руки/ОТКРЫТЫЙ ящик рядом, приёмник — игрок или открытый ящик; закрытый ящик недоступен. Спрайт `Structures/Storage/Crates/generic.rsi` (closed/open). SSR_CONTAINER_TEST. Доказано: открытие→взятие (slot=3)→закрытие→«item is not available to sender»

## Тело, одежда и предметы (изучение субагентами, 04.10.2026)

Изучены три среза сборки (тело/одежда, слоты инвентаря, поэлементные расхождения) —
вывод: арт `parts.rsi` в SS14 **нейтральный**, а цвет задаёт тонировка (кожа/глаза),
и поверх тела рисуются слои одежды. Сделано:

- **Тонировка**: части тела умножаются на `DEFAULT_SKIN` (#FFE1CC, как профиль Human:
  HSV(25°, 20%, 100%)), глаза — на `DEFAULT_EYES` (чёрный). До этого кукла показывала
  сырые цвета ассета («бледно-розовая»).
- **Одежда**: новый крейт-модуль `core/clothing.rs` — `ClothingSlot` (12 слотов),
  `Clothing` (слот → bits, реплицируется), состояния `equipped-INNERCLOTHING/FEET/HAND/...`
  и z-слои по порядку `base.yml`. Каталог предметов получил поля `slot` и `worn`;
  добавлены Рюкзак, Комбинезон инженера, Ботинки, Перчатки, Каска, Противогаз, Гарнитура.
  Клиент рисует надетые вещи поверх тела (`humanoid::sync_worn_clothes`), направление —
  общей системой `update_facing`.
- **Стартовый комплект** (как у ассистента/инженера): рюкзак, комбинезон, ботинки.
- **Инвентарь только с рюкзаком** (правило владельца, как в SS14): окно рюкзака не
  открывается, если слот `back` пуст; в хотбаре появились слоты экипировки
  (`Slots/id`, `Slots/belt`, `Slots/back`), клик по занятому слоту снимает вещь,
  клик по пустому — надевает предмет из активной руки (`Equip`/`Unequip`, протокол v8).
- **Подсветка под курсором** — не только шлюзы: жёлтая рамка вокруг предметов на полу
  и ящиков (как `InteractionOutline`).
- **z-порядок как в движке**: двери (1.5) выше тел (0.9/1.0), туман (0.85) ниже тел,
  спрайт предмета в руке рисуется в точке держателя (убран сдвиг +14/−6 — в арте
  inhand рука уже зашита).
- Протокол **v8** (`Equip`/`Unequip`). ВАЖНО: при добавлении реплицируемого компонента
  его `app.component::<C>().replicate()` обязан стоять в ОДНОМ порядке на сервере и
  клиенте — иначе клиент ловит «Hit the end of buffer, expected more data».

Сделано дальше: **карманы и разгрузка** как настоящие слоты (`ClothingSlot::Pocket1/Pocket2/
SuitStorage`, протокол v9: `Equip { item, slot }`) — в карман влезают только мелкие предметы
(SS14 `PocketableItemSize = Small`, проверка размера на сервере), разгрузка требует верхней
одежды (`dependsOn: outerClothing`); в хотбаре появились слоты `Slots/suit_storage` и два
`Slots/pocket` (группа MainHotbar справа от рук, как в `HotbarGui.xaml`).
**Обводка под курсором — по силуэту, а не квадратом**: у предметов рисуется 8 копий спрайта
со смещением на 1 px (аналог шейдера `SelectionOutline` в SS14), у шлюзов и ящиков остаётся
рамка по тайлу; тест-режим `SSR_HOVER_TEST=1` (считает курсор над первым предметом) — для
скриншот-проверки.

Сделано дальше: **окно персонажа** со слотами одежды (`InventoryGui` в SS14) — девять слотов
в сетке 3 колонки ровно по `uiWindowPos` шаблона человека (обувь 1,0; комбинезон 0,1; куртка
1,1; перчатки 2,1; шея 0,2; маска 1,2; уши 2,2; очки 0,3; голова 1,3), текстуры

Вещь можно надеть перетаскиванием из рюкзака прямо на слот, клик по занятому слоту снимает
вещь, по пустому — надевает из активной руки.

Сделано дальше: **варианты тела по полу** — `core::mechanics::Sex` (Male/Female/Unsexed,
реплицируется), половые части берутся только у head/chest/groin (`_f`), как
`HumanoidVisualLayersExtension.HasSexMorph` в SS14; пол на спавне — `SSR_SEX=female|male`
или «бросок монетки»; отпечаток тела включает пол, поэтому смена пола пересобирает куклу.
Проверено: `player body attached species=Human sex=Female parts=12`.

**Общий список репликации** переехал в `ssr_protocol::net::register_replication` (под фичей
`net`, с опциональной зависимостью на `ssr-core`) — сервер и клиент зовут одну функцию, так
что порядок регистрации больше не может разойтись (эту ошибку ловили трижды).
**Раскладка хотбара** приведена к `HotbarGui.xaml`: слева `SecondHotbar` (id, belt, back),
затем панель статуса, руки, панель статуса, справа `MainHotbar` (разгрузка, карман 1, карман 2);
